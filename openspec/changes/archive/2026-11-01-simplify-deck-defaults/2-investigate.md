## Findings

**Liveness is suppressed, then re-invented.** `packages/pi-stardeck/index.ts:530` calls `ctx.ui.setWorkingVisible(false)` on every TUI session start — the README (L63–64) documents that Pi's built-in `Working…` loader row (and its vertical space) is hidden. Nothing else touches native indicators: `setHiddenThinkingLabel` appears nowhere in the tree. Meanwhile `deck.ts:282` (`ACTIVITY_LABELS`) fabricates phase words from the header's kind projection (`understanding → 'interpreting'`, …) via `liveKindLabel` (L330) and legacy `activityLabel` (L301); `observedActivityLabel` (L338) prefers the precise title-state activity, else phase words; `activityTile` (L353) renders the dim `awaiting Human` placeholder whenever the label is empty but the band speaks on cost alone (`activityBandSpeaks` L346: `activitySpeaks || costSpeaks`). Restoring the native indicator (delete one call) plus deleting the fabricated voices leaves observed reality as the only narrator.

**The title fault is structural, not motivational.** The `title` tool (`packages/status/index.ts:1300`) carries the first-turn rule in its description; the previous change proved delivery still loses (every agent skips it). Pi's `before_agent_start` event exposes `messageType: "user"` with the raw `prompt` (extensions.md L216) — the status extension already subscribes (index.ts:1200, currently `runtime?.beginTurn()` only). The sanitizer exists: `sessionSubject('set', …)` (`active-work.ts:95`) bounds to `MAX_SUBJECT_POINTS = 120` (L31) via `shorten` (L37); persistence exists (`persistAndApplySubject` L1067 → `pi.appendEntry` + `runtime.setSubject`); restore exists (`restoreSessionSubject`); `applyTitleAction` (L1082) already refuses to write identical state. Auto-set only while `currentSubject()` is `clear` makes the agent call optional polish instead of a load-bearing bet.

**Task counts ignore the artifact the Human ticks.** `collectOpenSpec` (`packages/status/src/openspec.ts:297`) takes `completedTasks` from `instructionProgress?.complete ?? change.completedTasks` — CLI progress. The `spec` schema's execution artifact is `4-execute.md` with `## Slice N` headings and plain `- [x]` items (see archived `simplify-session-focus-surface`); `parseTaskHierarchy` (L121) expects `## Task <id>` + `- [ ] Step` + `### Human validation` and returns `undefined` for that shape; the CLI's own done-counting demonstrably did not advance during the last execution (Work tile pinned at `0/N` through 2026-10-30 despite ticked Slices). But the collector already reads the artifact file when `instructions apply` reports `contextFiles.tasks` (L200–212): `parseTaskMarkdown` (L152) replaces the CLI task list with honest done flags (`markdownTasks.length > 0 → tasks = markdownTasks`, L291). The truth is already parsed — only the counts ignore it.

**The four-line map already matches the Human's target.** Line 1: identity chips › path › git ∥ alert + engine (`projectDeckLeft` L412, `deckCornerRight`, `statusAlertTile`); line 2: subject ∥ work (`titleBandLines` L182, `workTile`); line 3: activity ∥ turn cluster + span rows; line 4: machine tail ∥ notices/ladybug (`machineCornerLadder`, `noticeTile`). Only line 3's voice changes; A/B/D are orthogonal to layout.

**Wiring facts for the refactor pass.** The umbrella `src/index.ts` is the only production identity: `surface: 'deck'` (plain widget mode). `editor-deck` exists for embedders (vim border `deckSurface`, exercised in `surface.test.ts`); the `legacy` widget branch (`runtimeHeaderWork`/`layoutLifecycleTitle`/`renderLifecycleTitleSections`, index.ts:614–618) has no production caller and no test. `deckMode` guards thread through every publisher (`publishFooter`, `publishPromptStatus`, `publishRuntimeFooter`, …) because one entrypoint serves three surfaces. The activity timer ticks at 50 ms for the whole busy window (`setInterval(refreshActivityAge, 50)`, index.ts:531) and `refreshActivityAge` early-returns only when idle — centisecond chronometer precision (`'cc` in `formatDeckElapsed`) is the reason for 20 Hz, but the timer runs even when nothing renders. `packages/pi-stardeck/src/title-state.ts` is a deliberate protocol-boundary copy of `packages/status/src/title-state.ts` (comment: no npm dependency across packages; event channel only) — duplication by design, not drift.

## Options

- **Auto-title trigger:** `before_agent_start` with `messageType === 'user'` (covers every Human prompt including resumes) vs a `message_end`/`session` hook (later, racy). First is strictly earlier and simpler.
- **Slash prompts:** skip prompts starting with `/` (commands are not subjects) vs titling them too. Skipping keeps `/council …` sessions untitled until real prose arrives; the title tool stays for deliberate naming.
- **Band lifecycle:** band exists only while an observed activity is live (pure) vs cost-only band retained. Pure matches the Human's "shouldn't display anything"; the turn chronometer rides the band and retires with it — Pi's restored indicator owns mid-turn liveness.
- **Count precedence:** artifact-parsed tasks first (file truth), then CLI instruction progress, then `list` counts — vs CLI first. File truth is what the Human edits; CLI first re-creates the 0/N bug.
- **Refactor reach:** behavior-preserving retirements with proof of no caller (legacy widget branch, timer duty cycle, `deckMode` guard folding) vs cosmetic-only. Dead-surface removal needs the package's export surface kept honest (`ContextHeaderOptions` narrows to what production and tests exercise).
